# 四步管线详述

## ① 人工跑通与规则沉淀

**做法**：前几家公司不交给 Agent，由人工完整跑完一整轮拆分：定位披露表、换算单位、对齐口径、铺报告期、填成品。

**产出**（后续所有自动化的输入）：

- 拆分口径清单：哪些板块要拆、每板块的项目粒度、哪些项要合并/拆分
- 字段结构：行序、四行指标组（名称 / yoy / 毛利率 / 占比）、板块间距
- 格式规范：日期列、数字格式、空值规则
- 取数来源与校验要点：每个数据点在哪张表、单位是什么、拿什么交叉验证
- 易错点清单：各家披露口径差异、改名链、披露缺口

**为什么必须人工先跑**：口径判断与易错点只能从实操里长出来；跳过这步直接自动化，等于把错误批量复制。

## ② Agent 设计与实现

**做法**：把人工的每一步抽象成 Agent 可执行的步骤，写进 `AGENTS.md`（作业说明书）：

- 任务定义与目录约定（文件放哪里、产物放哪里）
- 数据来源优先级（一手 > 补充 > 第三方；缺失期间如何标注）
- 字段与结构规则（行序、分组、命名、合计口径）
- 空值规则（未披露就是未披露）
- 输出格式（机器可校验的格式表）
- 红线与交付前自检清单

**关键**：说明书约束的是**取数范围与输出规范**，不是具体数据。这样换公司时只改特化段落，管线不动。

配套的自动化能力随后逐步补齐（爬取、解析、灌表、校验），工具箱在搭建期间乃至上线之后持续扩充。

## ③ 数据处理流程设计

### 数据收集

- 从披露渠道取原始文件（定期报告、招股说明书、业绩快报），按期间命名
- 补充数据从金融终端手工取数（缺失期间或不提供文本层的文件）
- **统一归入项目文件夹**，按公司 / 期间 / 板块分层，路径固定、命名固定

### 数据提取

- 原始 PDF → 文本层 → 解析成结构化中间表（每个板块一套）
- 中间表保存**提取值 + 期间 + 项目名**，并保留可审计的推导痕迹（推算值写明公式）
- 中间表是核心资产：成品表只从它读值

### 成果产出

- 脚本从中间表写入成品表模板：营收 / 成本 / 毛利率 / 占比 / yoy，按日期列定位
- 事实规则：**读值列与写值列是两套列号映射**（中间表用自己的期间列序，成品表按日期列定位），混用即错位

## ④ 复核审查

**AI 复核**（标准写在说明书里，由脚本 + 模型执行）：

- 格式：日期列齐全、金额两位小数、百分比格式、无占位符残留
- 数据：三向加总交叉验证（行业 / 产品 / 地区 ≈ 总收入）
- 结构：每项是否齐全四行、板块间距、项目名是否与原报告一致
- 发现即修正，并记录问题类型（用于反向完善说明书）

**人工终审**：

- 逐项过一遍成品，重点看：单位、口径变化年份、空值是否合理、改名链是否断裂
- 确认无误后交付

## 过渡产物与最终产物

| 层级 | 内容 | 是否交付 |
|---|---|---|
| 原始文件 | 年报 / 半年报 / 招股书 / 快报 | 否（工作底稿） |
| 中间表 | 按板块的结构化提取结果（含推导痕迹） | 视需要 |
| 成品表 | 标准化拆分表（可直接引用） | **是** |
| 校验报告 | 格式与交叉校验结果 + 已知空值清单 | 是 |
